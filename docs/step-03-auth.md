# الخطوة 3 — المصادقة

## الهدف

استبدال شاشة الدخول التجريبية بمصادقة حقيقية: حسابات مخزّنة في قاعدة البيانات، كلمات مرور
مُجزَّأة، جلسات قابلة للإبطال، وواجهة تعمل فعليًا مع الـ API — مع إبقاء التسجيل العام مغلقًا
بعد إنشاء أول مسؤول.

## النطاق المنفَّذ

### قاعدة البيانات

- نموذج `User` (`users`): بريد فريد، تجزئة كلمة المرور، الاسم الكامل، حالة التفعيل، آخر دخول.
- نموذج `RefreshSession` (`refresh_sessions`): جلسة خادم لكل تسجيل دخول.
  - يُخزَّن **هاش SHA-256** لرمز التحديث فقط، لا الرمز نفسه.
  - `expiresAt` و`revokedAt` وبيانات الجهاز/العنوان للإبطال والمراجعة.
  - حذف المستخدم يحذف جلساته (`onDelete: Cascade`).
- هجرة `20261113101759_auth`.
- الـ seed ينشئ مسؤول التطوير `admin@shadtech.local` بكلمة `ChangeMe123!` (قابلة للتغيير عبر
  `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD`)، ولا يعيد تعيين كلمة المرور عند إعادة التشغيل.

### الـ API

| المسار                  | الطريقة | الوصف                                           |
| ----------------------- | ------- | ----------------------------------------------- |
| `/api/v1/auth/status`   | GET     | هل توجد حسابات؟ يقود شاشة التهيئة الأولى        |
| `/api/v1/auth/register` | POST    | إنشاء أول مسؤول فقط، ثم يُغلق (`403`)            |
| `/api/v1/auth/login`    | POST    | تحقق من البيانات، يحدّث `lastLoginAt`، يبدأ جلسة |
| `/api/v1/auth/refresh`  | POST    | تدوير رمز التحديث وإصدار رمز وصول جديد          |
| `/api/v1/auth/logout`   | POST    | إبطال الجلسة ومسح الكوكي                        |
| `/api/v1/auth/me`       | GET     | بيانات المستخدم الحالي (محمي)                   |

- رمز الوصول: JWT لمدة **15 دقيقة**، يُعاد في جسم الاستجابة ويُحفظ في الذاكرة فقط.
- رمز التحديث: عشوائي 48 بايت، في كوكي `HttpOnly` باسم `shadtech_refresh`:
  - `Path=/api/v1/auth`، `SameSite=Lax`، `Secure` في الإنتاج، صلاحية **7 أيام**.
- كل عملية تحديث تُبطل الرمز السابق (rotation)؛ إعادة استخدام رمز قديم ترجع `401`.
- `JwtAuthGuard` يتحقق من التوقيع (issuer/audience) **ومن الجلسة في القاعدة**، لذا إبطال
  الجلسة يُبطل رموز الوصول الصادرة عنها فورًا.
- كلمات المرور عبر `scrypt` من Node (بدون اعتماديات أصلية)، وتُقارن بـ `timingSafeEqual`.
  عند عدم وجود البريد يُنفَّذ scrypt على هاش وهمي لتقريب زمن الاستجابة.
- الحدود: 120 طلبًا/دقيقة عامة، و5 محاولات/دقيقة لتسجيل الدخول والتسجيل، و30 للتحديث.

### الواجهة

- `lib/api.ts`: غلاف `fetch` موحّد — يضيف رمز الوصول، يرسل الكوكي، ويحدّث الرمز تلقائيًا مرة
  واحدة عند `401`.
- `lib/auth.tsx`: `AuthProvider` يستعيد الجلسة عند الإقلاع عبر كوكي التحديث، ويجدّدها كل 12
  دقيقة، ويوفّر `login`/`register`/`logout`.
- شاشة الدخول:
  - وضع دخول عادي، ووضع **تهيئة أول مسؤول** تلقائيًا عندما `initialized = false`.
  - تحقق محلي من البريد والاسم وطول كلمة المرور وتطابق التأكيد.
  - رسائل خطأ عربية لحالات `400/401/403/409/429` وانقطاع الشبكة.
- لوحة التحكم تعرض الاسم والبريد الحقيقيين وآخر دخول، وزر خروج يُبطل الجلسة فعليًا.
- شاشة إقلاع قصيرة أثناء استعادة الجلسة، مع الحفاظ على الوضع الفاتح/الداكن.

## التشغيل

```bash
npm install
npm run dev:db
npm run db:migrate   # أول مرة فقط
npm run db:seed      # ينشئ المسؤول الأول
npm run dev:api
npm run dev:web
```

- أنشئ `backend/.env` من `.env.example` وضع فيه `JWT_SECRET` (إلزامي في الإنتاج):

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

- الدخول التطويري: `admin@shadtech.local` / `ChangeMe123!` — غيّره قبل أي نشر حقيقي.
- على قاعدة فارغة بلا seed، تعرض الواجهة نموذج إنشاء المسؤول الأول بدل تسجيل الدخول.

## قرارات معمارية

| القرار                                  | السبب                                                |
| --------------------------------------- | ---------------------------------------------------- |
| `scrypt` من Node بدل bcrypt/argon2      | لا اعتماديات أصلية ولا حاجة لبناء native على Windows |
| رمز وصول في الذاكرة فقط                 | تقليل أثر XSS؛ لا `localStorage` للرموز              |
| رمز تحديث في كوكي `HttpOnly` + rotation | حماية من سرقة الرمز وإعادة استخدامه                  |
| التحقق من الجلسة داخل `JwtAuthGuard`    | إبطال فوري للجلسات بدل انتظار انتهاء JWT             |
| تسجيل أول مسؤول فقط                     | لا يوجد نظام دعوات/أدوار بعد (الخطوة 6)              |
| `204` عند التحديث بلا كوكي              | أول زيارة لا تُسجّل خطأ `401` في Console               |
| رسائل دخول موحّدة                        | عدم كشف ما إذا كان البريد مسجلًا                      |

## خارج النطاق

- استعادة كلمة المرور وتغييرها من الواجهة.
- تسجيل مستخدمين إضافيين ودعوات (الخطوة 6).
- الأدوار والأذونات وعزل المؤسسات (الخطوة 4).
- المصادقة الثنائية وسجل تدقيق الأحداث (الخطوة 8).

## ملاحظات تشغيلية

- `JWT_SECRET` غير المضبوط يعمل في التطوير بتحذير، ويرفض الإقلاع في الإنتاج.
- إعادة `npm run db:seed` لا تغيّر كلمة مرور مسؤول موجود.
- لحذف جميع الجلسات: `npm run db:studio` ثم حذف صفوف `refresh_sessions`، أو إعادة بناء القاعدة.
- بعد إعادة `db:reset` تصبح `initialized: false` وتعود شاشة تهيئة المسؤول.
