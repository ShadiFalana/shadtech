# الخطوة 2 — قاعدة البيانات

## الهدف

تأسيس طبقة بيانات حقيقية فوق الهيكل الأساسي: PostgreSQL محلي، Prisma كمُنظّم للمخطط
والهجرات، وربط فحص صحة الخدمة بحالة قاعدة البيانات — دون أي كيان تجاري بعد.

## النطاق المنفَّذ

- **PostgreSQL 18** محلي عبر حزمة `embedded-postgres` (لا يحتاج Docker أو تثبيتًا منفصلًا).
  - بيانات التطوير في `backend/.pgdata` (مستثناة من Git).
  - يُهيّأ العنقود بترميز `UTF8` ومحلّي `C` لضمان دعم كامل للنصوص العربية.
- **Prisma 6.19.3**:
  - مخطط في `backend/prisma/schema.prisma`.
  - هجرة أولى `20261112110351_init`.
  - نموذج `SystemSetting` فقط (`system_settings`) كإعدادات منصة عامة (مفتاح/قيمة JSON).
- **طبقة NestJS**:
  - `PrismaModule`/`PrismaService` عالمي مع إدارة دورة حياة الاتصال و`ping()`.
  - `ConfigModule` لقراءة `.env` (بما فيها `DATABASE_URL`).
  - `GET /api/v1/health` يفحص القاعدة فعليًا:
    - سليم: `200` مع `status: "ok"` و`checks.database.status: "up"` وزمن الاستجابة.
    - متعطل: `503` مع `status: "degraded"` و`checks.database.status: "down"`.
- **بيانات أولية (seed)**: 3 إعدادات تشمل اسم المنصة بالعربية للتحقق من سلامة الترميز.
- **الواجهة**: لوحة التحكم تعرض حالة القاعدة وزمن استجابتها، والخطوات القادمة تبدأ من المصادقة.

## التشغيل

من جذر المشروع:

```bash
npm install
npm run dev:db    # طرفية 1 — PostgreSQL على 127.0.0.1:5432
npm run db:migrate # أول مرة فقط (أو db:deploy لاحقًا)
npm run db:seed    # أول مرة فقط
npm run dev:api    # طرفية 2 — http://localhost:3001/api/v1
npm run dev:web    # طرفية 3 — http://localhost:5173
```

> أوامر قاعدة البيانات معرّفة كسكربتات جذر تُمرَّر إلى حزمة الخلفية.

## التحقق المنفَّذ

| الفحص | النتيجة |
| --- | --- |
| `npm run typecheck` (الخلفية والواجهة) | ✅ بلا أخطاء |

| إعادة تشغيل القاعدة | ✅ عاد `200` تلقائيًا دون إعادة تشغيل API |
| الواجهة | ✅ تعرض «قاعدة البيانات: تعمل» وزمن الاستجابة، بلا أخطاء Console |

## قرارات معمارية

| القرار | السبب |
| --- | --- |
| `embedded-postgres` بدل Docker | Docker/WSL غير متاحين على بيئة التطوير الحالية |
| Prisma 6 بدل 7/8 | تجنّب تغييرات كبيرة في التهيئة والـ seed؛ الترقية لاحقًا بقرار منفصل |
| ترميز `UTF8` + `locale=C` | منع إنشاء عنقود `WIN1252` على Windows وتعطّل النصوص العربية |
| مخطط أدنى في هذه الخطوة | كل كيان تجاري يُضاف في خطوته المعتمدة، مع هجرته الخاصة |
| إبقاء API يعمل عند تعطل القاعدة | يسمح لفحص الصحة بالإبلاغ عن الحالة المتدهورة بدل انهيار الخدمة |

## خارج النطاق

- المصادقة والجلسات.
- الأدوار والعزل بين المؤسسات (`tenant_id`).
- كيانات الشركات والمستخدمين والعملاء والتذاكر.
- نسخ احتياطي واستعادة آلية (تُضاف مع خطوة العمليات).

## ملاحظات تشغيلية

- لا يُشحن `psql` مع الحزمة؛ استخدم Prisma أو `npm run db:studio` لفحص البيانات.
- إيقاف `dev:db` يوقف العنقود، والبيانات تبقى في `backend/.pgdata`.
- لإعادة بناء قاعدة التطوير من الصفر: `npm run db:reset` ثم `npm run db:seed`.
